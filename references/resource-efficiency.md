# 内存、空间与响应优化（v1.0 开发版）

撤销仍保留最近 10 次完整操作。历史快照共享未变化的图件、组图与数据记录；恢复时克隆为当前可编辑状态，避免一次编辑污染其他撤销记录。无变化输入通过快照身份比较，不重复序列化整份项目。关闭和重开仍恢复 10 次操作。

工作流历史使用 `records-v1` 无损记录池再 gzip 压缩，降低反复保存相同图件的传输与内存开销。服务器明确声明支持时才发送记录池；尚未重启的旧服务器收到完整旧式快照。旧 JSON / gzip 历史自动兼容。解码同时限制展开后的历史大小（20 MB），不能通过大量引用绕过边界。

大型 SVG、组图子 SVG 和对象检查元数据在后端缓存中无损压缩；取用时恢复完整内容。缓存同时限制条目与估计对象占用，单个超大图保留一个可用条目，因此上限为软限制。完整对象、多选范围、误差关联和统计输入保持。

只读的组图验证和渲染复用来源的原轴信息，并独立复制可编辑字典；公开 `resolve_panel` 的默认结果仍完全独立。临时预览只复制目标图和可能联动的组图。三维投影、点形和颜色在每次对象检查中按轴 / 集合读取一次，颜色对应回观测身份。组图拖动先读布局再写，实际位置未变的子图和标注不重复更新。

重新打开时只复制字节已变化的运行模块；自动保存不重复写未变的复现入口。`project.fam.json` 和 `settings.json` 仍为可读标准 JSON，并原子保存。历史修订快照改为完整 `.json.gz`，与旧 `.json` 一起按修订号最多保留 30 个；旧快照可离线无损压缩。正常运行不创建开发验证项目；只存在当前原子写入暂存文件，完成后替换目标文件。

当前工程的已完成验证副本和源代码备份按目录打包为 ZIP，附 `__compaction_manifest__.json`（逐文件 SHA-256 和原大小），逐个校验后才移除重复目录。原始项目中的数据、源码、图形捕获、用户修改、导出和正式依赖均保留。备份在 `archives`，完整来源验证分片在 `verification/full-source-review-20261013/shards.zip`；解压对应 ZIP 即可还原原目录内容。依赖和正常启动缓存继续保留。

开发者复测使用 `tools/qa/resource_efficiency.py before|after` 建立隔离的 81 图项目，再运行 `resource_backend.py` 和 `resource_history.py`；最终可通过 `tools/compact_storage.py --apply --release-qa` 校验并释放这一可重建副本。这些工具只用于开发验证。大组图首次绘制仍需计算与浏览器布局，不能保证任意复杂图均即时响应。


## 第二轮响应与占用整理

纯界面操作显式采用 UI-only 更新：编辑层、移动模式、宽度应用范围等仅保存界面偏好，不创建整份科学记录历史快照；导出格式/代码语言等局部选项不发起项目保存。实际字体、颜色、范围、几何与数据展示修改仍使用完整可撤销事务。属性面板先在脱离文档的容器构建，再一次替换；轴/系列选择、未提交草稿、焦点和滚动保留。

锁定检查跳过设置相同的子图，改变的面板只读合并；直接修改锁定对象/图层仍拒绝。前端完整视觉签名按精确内容共享标识，最多64个、约4MB；缓存键也计入内存预算，退役签名清理对应缓存。单个超大图仍完整保留，不能裁剪观测、多选范围或撤销步骤。

本机精简的 Playwright 运行目录可将 bundled node.exe 无损压缩保存为 node.exe.zip：仅在系统 Node 满足本机驱动 package.json 的最低版本且实际CLI/浏览器测试通过后移除重复可执行文件。原字节、大小和SHA-256保留在包中；以后找不到兼容Node时，bootstrap校验并原子恢复原版本，无需联网。用户显式 PLAYWRIGHT_NODEJS_PATH 不覆盖。普通未精简安装继续使用原捆绑版本，启动不自动删除依赖。

已完成的 axis-scales-20261014、heavy-user-20261014、resource-efficiency-20261014 备份保存在 archives 对应ZIP，逐文件清单校验后压缩原目录；需要检查旧源码基线时先解压其ZIP。既有原数据、输入、捕获、用户设置及导出不参与整理。

## 已知来源文件的重复扫描

原数据保护继续在保存前核对登记文件的身份、路径和内容变化；发现阶段用 scandir 驱动的目录遍历读取名称，已登记且刚验证的文件不再重复调用 is_file。仍遍历每层目录、发现新输入/捕获并登记哈希，排除 __pycache__，不随目录链接越界。缺失、改写和清单篡改仍拒绝保存。

这只减少来源发现的重复系统调用，不能把此阶段计时当作全部保存或浏览器交互耗时。路径节点刷新同样只缓存当前路径结构和复用一帧矩阵，不丢弃曲线控制点或减少撤销记录。

## 重复绘制与对象关系缓存

同一图件、面板和视觉设置的并发预览请求合并，强制刷新仍独立请求。过期响应及其错误不覆盖当前画面或加载提示。只读对象检查直接读取缓存元数据，不解压一份立即丢弃的 SVG；已有完整关联不因轻量刷新退回截断列表。缓存仍遵守原条目和字节预算。

子图 SVG 命中准备缓存后仍核对捕获文件的身份和内容变化，不能仅依赖修改时间。左侧图库沿用统一同步入口，取消重复同步包装与列表观察器；搜索、全选、删除、恢复继续即时更新。

API 的标准 JSON 转换对已有效的字典 / 列表共享只读容器，仅复制包含 NaN、无穷大或 NumPy 值等需转换的分支；缺失仍为 null，原始行不回写。接口省去无意义分隔空格，项目 JSON、完整要素与撤销次数保持。

大图对象元数据进入压缩缓存前也执行同一有限 JSON 转换，兼容 NumPy 布尔值、整数与缺失值。该转换只作用于预览元数据，不写回捕获或统计输入；回归需包含全图字体变更和缓存命中后的完整对象检查。


## 右侧草稿与来源检查（2026-10-16）

一次同步的预览、组合图读取或保存中共享已成功的来源校验；退出即释放，异常也恢复。不同线程使用各自的范围，不能沿用上一次请求的校验结果；明确的 force 校验始终重新计算哈希。Windows 批量读取文件元数据，并查询实际 ChangeTime：Python 3.10 的 st_ctime 是创建时间，不能单独用它识别“内容改变但大小 / 修改时间被恢复”。无法取得 ChangeTime 时重新计算内容哈希。

关闭右侧对象编辑器清空表单、搜索引用和预览节点。滚动编辑栏、阅读帮助不触发预览；坐标范围输入框的自定义滚轮仍派发输入通知，及时显示新范围。实际字段编辑继续防抖，应用、取消、完整撤销与锁定保持。

同一隔离的 81 张来源图 / 24 子图工作负载实测：单图草稿后端暖缓存中位约 127→69 ms，组图草稿约 137→83 ms；这些不是完整界面耗时。三维角度输入到预览约 565→498 ms，24 子图首次打开仍约 2.2 秒。文件完整性补强会给部分读取 / 保存增加少量开销，不能宣称全部操作均同比加速。反复开关编辑器后表单节点归零；整页 JS 堆约 14 MB，本轮没有测得整页堆显著下降。

旧验证输出在 verification 内就地无损压缩为同名 ZIP，逐文件 SHA-256 校验后才移除展开副本；解压到原同名子目录可恢复。科研项目、来源、用户导出、完整历史、依赖和当前教程图片不参与这次整理。正常使用不会创建性能验证项目。


## 大组图缓存与按需参数（2026-10-17）

完整组合图复用现有的有界压缩 LRU，键包含组图布局、标注、透明背景、共享图例设置及各来源的当前视觉签名 / 文件时间。仍在命中前核对来源状态；不因缓存跳过原数据保护。修改一个子图只重绘必要的来源，撤销可复用此前的完整结果。缓存共用 64 MB 软预算，单张超大图仍保留完整内容。

常用文字、散点、颜色和坐标范围编辑器先构建当前常用参数；“位置、排列与全部相关参数”按需展开，也可点击顶部“全部相关参数”。没有单独常用表单的对象、三维编辑仍直接显示适用参数。展开前后的草稿一致，取消、应用、搜索、锁定和撤销保持。组图字母标注的全部适用参数已在常用表单内，不再提供无效的高级跳转。

Windows 对同目录较多来源使用 FileIdBothDirectoryInfo 批量读取实际 ChangeTime 和文件 ID，并与名称、大小、修改时间核对。Python 3.10 的 DirEntry.stat 不提供文件 ID 时，把原生文件 ID 加入签名。平台不支持、身份或文件版本不一致、链接路径仍回到原逐文件检查；强制校验始终读取全部内容哈希。回归包含同大小 / 恢复修改时间的直接改写、硬链接改写、文件替换、清单变更、缺失和回退路径。

同一 81 张来源图 / 78 图型、24 子图的交替测量中，后端暖缓存视图中位约 105→50 ms，来源状态核对约 84→38 ms；这是具体本机工作负载的后端计时，不能代表首次生成或所有浏览器操作。81 张来源图和两张组图的 SVG 逐字节保持。已完成的 18 个开发验证目录无损打包，逐文件 SHA-256 核验后移除展开副本，释放约 26.2 MiB；原目录名对应同名 ZIP，含恢复用清单，不处理科研输入、保存设置、导出、完整历史或依赖。

同一浏览器的常用坐标范围编辑器对比：初始表单节点 343→85、控件 57→13，打开中位约 26.6→17.6 ms；打开后的 JS 堆约 3.77→3.52 MB，DOM / 渲染侧占用约 5.37→4.20 MB。点击高级入口仍生成全部适用参数；关闭后表单节点归零。单页样本不能代表系统总进程内存。


## 稠密对象参数与失效画布引用（2026-10-18）

观测选择下拉框超过 80 项时，参数栏初始只创建当前选中项；聚焦或按下指针时一次载入完整清单，之后沿用标准键盘、鼠标及辅助功能操作。这个延迟载入只用于右侧“联动观测对象”控件，不裁剪科学元数据、框选数量或批量修改范围；小列表仍直接显示全部选项。选项用 DOM 文本赋值保留特殊字符，观测名称不随界面语言翻译。

显式聚焦对象时先确定最终编辑层和对象，再构建一次参数栏。重绘后清除仍引用旧 SVG 的选择几何缓存；最后一项图件从图库移除时，清空前端预览、检查、签名、挂载与选择引用，提交成功后也释放后端预览缓存。来源、导出、删除记录和完整撤销保留，恢复时重新从捕获构建。不能为了省内存缩减观测、从属误差或撤销。


## 折叠参数与预览请求生命周期（2026-10-20）

右侧“整层外观与显示”“系列与线段样式”和内嵌三维区只在展开或搜索时构建隐藏控件；层锁定入口始终可用。加载器通过 WeakMap 与对应 DOM 共同释放，不缓存已丢弃的属性面板。搜索先补齐适用参数再匹配，恢复搜索、切换层、字体和颜色操作沿用原逻辑。双击打开的高级参数已有同步草稿上下文，必须在该上下文内构建，不能把延迟回调留到真实项目状态后执行。

对象编辑器的预览运行状态、待更新标记和 AbortController 由每次打开的编辑器独立持有。关闭、取消或应用时终止浏览器仍在等待的预览请求；旧编辑器结束后不能阻塞、重排或更新新编辑器。POST 请求与 GET 一样传递可选 signal。已在后端开始的绘图可能仍会计算完毕，取消不等于能强制中断原生计算，也不省略真实保存验证。

同一 81 张来源图项目、同一浏览器交替前后对照，数据层初始控件 60→45、文字层 29→18、图例层 80→69；对应属性面板重建中位约 7.3→5.7 ms、6.1→4.05 ms、11.9→11.2 ms。这是面板构建耗时，不能表述为所有操作或后端分析都同比变快。整个浏览器页的 JS 堆样本约减少 1 MB，仍受图件、历史与垃圾回收影响，不等于系统总进程内存节省。

验证必须包含全部来源图层、搜索能发现未构建字段、展开后的参数编辑、双击高级参数草稿的应用 / 取消、真实颜色修改与撤销，以及关闭一个故意延迟的预览后立即打开下一编辑器。稠密观测、完整数据、关联误差和十步撤销不能为了响应速度被裁剪。
